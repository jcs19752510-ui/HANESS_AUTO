# 자동화 트리거 예시 (ORCHESTRATOR.md 3장 참고)

이 폴더는 12단계 하네스를 사람이 수동으로 `Agent` 도구를 호출하는 대신, 이벤트에 반응해 자동으로 실행하고 싶을 때 쓰는 **예시/출발점**이다. 실제 동작하려면 프로젝트의 CI 시스템, 브랜치 전략, 그리고 "이 단계 에이전트를 무엇으로 실제 실행할지"(Claude Code CLI를 헤드리스로 돌릴지, 별도 스크립트로 대체할지 등)를 팀이 직접 채워 넣어야 한다. 여기 있는 명령어는 **플레이스홀더**이며 그대로 복사해서 돌아간다고 가정하지 않는다.

## 파일
- `github-actions-harness.yml` — GitHub Actions 예시. 브랜치/태그 이벤트에 따라 5~10, 12단계를 매핑하고, 11단계(배포)는 GitHub Environments의 `required reviewers` 보호 규칙으로 사람 승인 없이는 절대 실행되지 않도록 게이트를 건다.
- `git-hooks/post-merge.sample` — work unit 브랜치가 로컬에 병합됐을 때 6단계(단위테스트)를 자동으로 트리거하는 훅 예시.

## 절대 자동화하면 안 되는 것 (다시 강조)
- **11단계 실제 배포 실행**은 CI가 아무리 정상이어도 사람의 명시적 클릭/승인 없이 실행되게 만들지 않는다 (규칙 E).
- **규칙 A의 질문 목록**이 발생하는 상황은 자동 파이프라인을 강제로 계속 돌리지 않고, 사람에게 알림을 보내고 그 단계에서 대기 상태로 멈춘다 (예: CI 잡을 실패시키지 말고 "대기(pending)" 상태로 두고 Slack/이메일 등으로 알림).

## 실제 적용 순서 (권장)
1. 먼저 5~10, 12단계를 CI에서 자동 실행하도록 연결한다 (질문 발생 시 정지하는 로직 포함).
2. 11단계는 마지막까지 수동 승인 게이트로 남겨둔다.
3. 파이프라인이 안정화된 후에만 git hook 기반의 로컬 자동화(5→6)를 추가로 도입한다.
